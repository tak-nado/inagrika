# Пояснение программы генерации тестовых данных и статистики

## 1. Связь с заданием

По условию кейса производственный датасет и историческая статистика хозяйства не
предоставляются и не требуются. Для цифровой проверки команда должна создать
собственные воспроизводимые входные данные, проверить допустимость вариантов и
сохранить прогноз времени, пути, покрытия и причины выбора.

`generate.py` формирует синтетическую XLSX-таблицу для такой программной
проверки. Числа являются авторскими тестовыми условиями, а не статистикой
реального предприятия.

Набор из 162 строк дополняет проверку алгоритма. Генератор также создаёт
отдельный `required_scenarios.xlsx` со сценариями А–Г из таблицы 1 задания.

## 2. Назначение программы

Генератор выполняет только подготовку исходных данных:

1. Перебирает отношения характеристик двух машин.
2. Создаёт числовые параметры машин.
3. Формирует стартовые положения для двух направлений проходов.
4. Сохраняет таблицу в `.xlsx`.

Генератор не строит маршруты, не проверяет столкновения и не выбирает
победителя. Эти операции выполняет приложение Inagrika.

Разделение генерации и проверки необходимо, чтобы тестовые данные не зависели от
результатов алгоритма, который ими проверяется.

## 3. Какие требования поддерживает генератор

| Пункт задания | Роль генератора |
| --- | --- |
| Шаг 1.2 | Создаёт варианты с равными и различающимися машинами |
| Шаг 1.3 | Фиксирует числовые входы, единицы и исходные допущения |
| Шаг 2.2 | Даёт данные для проверки равного деления |
| Шаг 2.3 | Даёт комбинации для сравнения распределений и направлений |
| Шаг 2.4 | Подготавливает стартовые позиции для проверки совместного движения |
| Таблица 1, А–Г | Создаёт отдельный файл обязательных сценариев |

## 4. Принцип формирования 162 сценариев

Для первой машины задаётся отношение ко второй по четырём характеристикам:

- ширина захвата `l`;
- рабочая скорость `U`;
- длина корпуса `hx`;
- ширина корпуса `hy`.

Для каждой характеристики используются три состояния:

- `=` — параметры равны;
- `>` — параметр первой машины больше;
- `<` — параметр первой машины меньше.

Все комбинации повторяются для проходов вдоль X и вдоль Y:

```text
2 направления × 3⁴ комбинации = 162 сценария
```

Такой полный перебор позволяет проверить, как выбор стратегии зависит не только
от производительности, но и от габаритов и возможности выполнения манёвров.

## 5. Исходные значения

Базовая машина имеет параметры:

| Параметр | Значение |
| --- | ---: |
| Ширина захвата | `6.0 м` |
| Рабочая скорость | `2.0 м/с` |
| Длина | `5.0 м` |
| Ширина | `3.0 м` |

Вторая машина всегда получает базовые значения. Первая машина изменяется в
соответствии с требуемым знаком.

| Параметр первой машины | `<` | `=` | `>` |
| --- | ---: | ---: | ---: |
| Захват `l1`, м | `4.5` | `6.0` | `8.0` |
| Скорость `U1`, м/с | `1.5` | `2.0` | `3.0` |
| Длина `hx1`, м | `4.0` | `5.0` | `6.0` |
| Ширина `hy1`, м | `2.5` | `3.0` | `3.5` |

Для всех 162 строк используются поле `240 × 120 м` и разворотная зона `10 м`.

Дополнительные характеристики вычисляются так же, как в основном приложении:

```text
Vtravel = U × 1.25
Vturn = U × 0.75
R = max(2.5, hx / 2, hy / 2)
```

## 6. Стартовые положения

### Проходы вдоль X

- первая машина начинает у левой нижней части поля;
- вторая — у левой верхней части;
- ориентация обеих машин равна `0°`.

### Проходы вдоль Y

- первая машина начинает у нижней левой части;
- вторая — у нижней правой части;
- ориентация обеих машин равна `90°`.

Координаты смещаются от границы на половину ширины захвата, чтобы центр рабочей
полосы находился внутри поля.

## 7. Структура сгенерированного XLSX

| Группа | Столбцы |
| --- | --- |
| Идентификатор | `scenario_id` |
| Геометрия | `s`, `field_x`, `field_y`, `turn_zone_width` |
| Заданные отношения | `cond_l`, `cond_U`, `cond_hx`, `cond_hy` |
| Захват | `l1`, `l2` |
| Рабочая скорость | `U1`, `U2` |
| Переезд | `Vtravel1`, `Vtravel2` |
| Разворот | `Vturn1`, `Vturn2` |
| Габариты | `hx1`, `hy1`, `hx2`, `hy2` |
| Радиус | `R1`, `R2` |
| Старт | `coord1_x`, `coord1_y`, `coord2_x`, `coord2_y` |
| Ориентация | `orient1`, `orient2` |
| Справочная оценка | `propusk_%` |

Поле `propusk_%` рассчитывается как остаток от деления поперечной ширины на
ширину захвата. Это только предварительная справочная оценка. Она не является
полной проверкой покрытия и не учитывает окончательное распределение маршрутов.

## 8. Получение расчётной статистики

Сам `generate.py` создаёт только входную таблицу. Расчётная статистика появляется
после обработки этой таблицы приложением.

Для каждой стратегии сохраняются:

| Показатель | Назначение |
| --- | --- |
| `T_strat*` | Время завершения последней машины |
| `T1_strat*`, `T2_strat*` | Время каждой машины |
| `deadhead_strat*` | Порожний путь пары |
| `overlap_strat*` | Расчётная площадь перекрытия |
| `turns_strat*` | Количество разворотов |
| `delay_strat*` | Задержка запуска для устранения конфликта |
| `status_strat*` | Допустимость или причина отклонения |
| `Winner` | Выбранная стратегия |
| `Winner_time` | Итоговое время выбранной стратегии |

Эти показатели позволяют сравнивать базовый и улучшенные способы по критериям,
указанным в задании: сначала время, затем порожний пробег и перекрытие.

## 9. Обязательные сценарии А–Г

В задании отдельно установлены следующие проверки:

| Код | Поле | Захват | Условие | Состояние в проекте |
| --- | --- | --- | --- | --- |
| А | `240 × 120 м` | По `6 м` | Одинаковые машины | Сформирован |
| Б | `120 × 240 м` | По `6 м` | Выбор направления при фиксированных стартах | Сформирован |
| В | `240 × 120 м` | По `6 м` | Вторая машина медленнее первой | Сформирован |
| Г | `250 × 130 м` | По `6 м` | Размеры не кратны захвату | Сформирован |

Результаты, маршруты, задания роботам и причины выбора сохраняются программой
`verification.py` в каталоге `deliverables`.

## 10. Дополнительные проверки из задания

Помимо числовых сценариев, задание требует проверить:

- одновременный подход машин к общей зоне;
- временную остановку;
- устаревшую телеметрию;
- восстановление работы после остановки;
- невозможность выполнения при ограничениях.

Цифровая модель проверяет геометрические конфликты, ожидание и задержку старта.
Проверки реальной телеметрии и восстановления робота не входят в объём проекта.

## 11. Порядок использования

1. Установить зависимости:

   ```powershell
   python -m pip install -r requirements.txt
   ```

2. Создать синтетическую таблицу и отдельные сценарии А–Г:

   ```powershell
   python generate.py
   ```

3. При необходимости указать другой файл:

   ```powershell
   python generate.py --output scenarios.xlsx
   ```

4. Открыть `dist\Inagrika.exe`.
5. На вкладке «Загрузить таблицу» выбрать созданный XLSX.
6. Запустить расчёт и сохранить отдельный результирующий XLSX.

Поддерживается только `.xlsx`. Количество строк в проверяемом файле не
ограничено 162 сценариями.

## 12. Критерии проверки генератора

Генератор считается работающим корректно, если:

- создаётся ровно 162 строки;
- присутствуют оба направления `x` и `y`;
- каждая комбинация четырёх знаков встречается для каждого направления;
- числовые значения соответствуют указанным отношениям;
- стартовые координаты находятся внутри поля;
- файл открывается приложением без преобразования формата;
- повторный запуск с теми же параметрами создаёт тот же набор данных.

## 13. Ограничения

- Матрица 162 комбинаций использует одно поле `240 × 120 м`; другие размеры
  представлены отдельными сценариями А–Г.
- `propusk_%` остаётся предварительной характеристикой исходного захвата;
  окончательное покрытие рассчитывает планировщик.
- Реальные роботы, телеметрия и натурные испытания не входят в объём проекта.
