# Пояснительная записка к приложению Prime

## 1. Основание для разработки

Приложение разработано по кейсу «Разработка системы планирования
автоматизированной уборки (АТ10-3)» олимпиады «Иннагрика 2026».

По условию требуется спланировать совместную работу двух автономных комбайнов
на прямоугольном поле. Система должна учитывать различие характеристик машин,
рабочие проходы, переезды, развороты, ожидание и возможные конфликты. Главный
критерий — время от общего запуска до безопасного завершения работы последней
машиной.

Проект ограничен цифровым планировщиком и программной проверкой маршрутов.
Шаги 1.4, 2.5 и 2.6, относящиеся к реальным роботам, телеметрии и физическому
финалу, исключены из объёма проекта и не учитываются в прогрессе.

## 2. Постановка задачи

Входными данными являются:

- длина и ширина обрабатываемой части прямоугольного поля;
- направление рабочих проходов;
- ширина заранее убранных разворотных зон;
- ширина захвата каждой машины;
- рабочая скорость, скорость переезда и скорость разворота;
- длина, ширина и минимальный радиус поворота машин;
- стартовые координаты и ориентация машин.

По этим данным программа должна:

1. Построить несколько пар маршрутов.
2. Проверить геометрическую допустимость разворотов.
3. Проверить совместное движение машин во времени.
4. При необходимости разнести движение задержкой запуска.
5. Рассчитать показатели каждой машины и всей пары.
6. Выбрать лучший допустимый вариант.
7. Сохранить конфигурацию, маршруты и результаты.

## 4. Архитектура программы

Программа разделена на два основных модуля.

### `main.py`

Отвечает за:

- графический интерфейс PyQt6;
- чтение и сохранение XLSX;
- проверку входных данных;
- пакетную обработку таблиц любого размера;
- расчёт частного сценария;
- отображение и экспорт схемы;
- формирование отчёта.

### `planner.py`

Содержит независимое расчётное ядро:

- модели поля, машины, сегмента, маршрута и плана;
- построение рабочих проходов;
- построение переездов и разворотов;
- расчёт трёх стратегий;
- проверку столкновений;
- подбор задержки запуска;
- выбор лучшего варианта.

Такое разделение изолирует интерфейс от расчётной модели и упрощает тестирование.

## 5. Цикл уборки — пояснение к шагу 1.1

Маршрут каждой машины состоит из следующих этапов:

1. **Выход к первому проходу** — порожнее движение от стартовой позиции.
2. **Рабочий проход** — прямолинейное движение с включённым рабочим режимом.
3. **Разворот** — переход к следующему проходу внутри разворотной зоны.
4. **Переезд** — движение без обработки, включая путь вдоль границы поля.
5. **Ожидание** — задержка старта для предотвращения столкновения.
6. **Завершение** — выход к внешней границе и безопасная остановка.

Основной показатель пары машин:

```text
T_pair = max(T_machine_1, T_machine_2)
```

Поэтому минимальная длина маршрута одной машины не гарантирует минимальное время
работы пары. Если первая машина заканчивает быстро, а вторая получает слишком
большую область или вынуждена долго ждать, итог определяется второй машиной.

## 6. Способы организации — пояснение к шагу 1.2

### 6.1. Равное деление поля

Поперечная ширина поля делится на две равные прямоугольные части. Каждая машина
последовательно обрабатывает свою область.

Вариант предпочтителен, если машины имеют близкую ширину захвата, скорость и
манёвренность. Это базовый алгоритм из шага 2.2.

### 6.2. Распределение полос

Рабочие проходы выдаются машинам через один. Проверяются два варианта: первую
полосу получает первая или вторая машина.

Вариант может быть полезен при близкой производительности машин, но способен
увеличить порожние перемещения и число общих зон движения.

### 6.3. Деление по производительности

Производительность машины оценивается как:

```text
P = l × U
```

где `l` — ширина захвата, `U` — рабочая скорость.

Доля поперечной ширины для первой машины:

```text
share_1 = sweep_width × P1 / (P1 + P2)
share_2 = sweep_width - share_1
```

Вариант предпочтителен при заметной разнице ширины захвата или рабочей скорости.

## 7. Расчётная модель — пояснение к шагу 1.3

### 7.1. Геометрия поля

`field_x` и `field_y` задают размеры только обрабатываемой части поля.
Разворотные зоны считаются заранее убранными, добавляются снаружи с обоих концов
рабочего прохода и учитываются во времени и пробеге.

```text
run_length = field_length
```

При проходах вдоль X:

```text
field_length = field_x
sweep_width = field_y
```

При проходах вдоль Y:

```text
field_length = field_y
sweep_width = field_x
```

Полный габарит координатной области:

```text
проходы вдоль X: total_x = field_x + 2 × turn_zone_width, total_y = field_y
проходы вдоль Y: total_x = field_x, total_y = field_y + 2 × turn_zone_width
```

### 7.2. Количество проходов

Для области шириной `region_width` и захвата `l`:

```text
pass_count = ceil(region_width / l)
```

Проходы равномерно размещаются внутри выделенной области.

### 7.3. Перекрытие

Если ширина области не кратна захвату:

```text
overlap_width = pass_count × l - region_width
overlap_area = overlap_width × run_length
```

Модель объединяет полосы покрытия, рассчитывает непокрытую площадь и отклоняет
план, если доля пропусков превышает `allowed_gap_percent`.

### 7.4. Время движения

Для прямолинейного сегмента:

```text
segment_time = segment_length / segment_speed
```

Для дуги разворота:

```text
arc_time = arc_angle × turn_radius / turn_speed
```

Время машины включает работу, порожние переезды, развороты и задержку запуска.

### 7.5. Пример упрощённого расчёта

Для рабочей части поля `240 × 120 м`, проходов вдоль X, разворотных зон по
`10 м`, захвата `6 м` и равного деления полный габарит маршрута равен
`260 × 120 м`:

```text
run_length = 240 м
region_width = 120 / 2 = 60 м
pass_count = ceil(60 / 6) = 10 проходов на машину
work_distance = 10 × 240 = 2400 м
```

При рабочей скорости `2 м/с` чистое рабочее время равно `1200 с`. Итоговое
время программы больше, потому что дополнительно учитываются выход к проходу,
развороты, переезды, возможное ожидание и безопасное завершение.

## 8. Модель разворота

Если расстояния между соседними проходами достаточно, используется манёвр из
двух четвертей окружности и прямого участка. Для близких проходов применяется
петлевой RLR-манёвр из трёх дуг.

Для проверки разворотной зоны учитываются радиус траектории и габариты машины.
Маршрут отклоняется, если необходимая область больше доступной разворотной зоны.

Движение задним ходом в текущей модели не используется.

## 9. Совместное движение — пояснение к шагу 2.4

Машина аппроксимируется окружностью, покрывающей корпус и жатку:

```text
collision_radius =
    sqrt((length / 2)² + (max(width, header) / 2)²)
    + safety_margin
```

Для каждого общего временного интервала вычисляется минимальное расстояние между
движущимися машинами. Конфликт фиксируется, если:

```text
distance <= collision_radius_1 + collision_radius_2
```

Проверяются рабочие проходы, переезды, развороты, ожидание и стоянка после
завершения. Простое пересечение линий маршрутов не считается столкновением без
одновременного занятия пространства.

Если обнаружен конфликт, перебираются задержки одной из машин:

```text
0, 5, 10, ..., 180 секунд
```

Выбирается безопасный вариант с минимальным итоговым временем.

## 10. Выбор лучшего решения

Недопустимые маршруты не участвуют в сравнении. Допустимые планы сравниваются:

1. По минимальному времени завершения последней машины.
2. При близком времени — по минимальному порожнему пробегу.
3. Затем — по минимальной площади перекрытия.

Это соответствует установленному в задании порядку критериев.

## 11. Реализация шага 2.1

### Пакетный режим

Вкладка «Загрузить таблицу» принимает XLSX с любым количеством сценариев.
Показываются первые 100 строк, но проверяются все строки. Расчёт выполняется в
фоновом потоке и сохраняется в отдельный XLSX.

### Частный режим

Вкладка «Рассчитать частный случай» принимает размеры рабочей части поля и
параметры машин. Разворотные зоны в размеры X и Y включать не нужно: приложение
добавляет их вдоль выбранного направления проходов.
Выбранное направление применяется ко всем трём стратегиям. Для сравнения X и Y
нужно выполнить два отдельных расчёта. Интерфейс показывает маршруты, переезды,
манёвры, покрытие и разворотные зоны.

Отчёт частного сценария содержит:

- `configuration` — исходные параметры;
- `results` — показатели и выбранную стратегию;
- `route_machine_1` — временные сегменты первой машины;
- `route_machine_2` — временные сегменты второй машины.

Карта маршрутов сохраняется отдельно в PNG.

## 12. Входная XLSX-таблица

Обязательные столбцы:

| Столбец | Содержание |
| --- | --- |
| `s` | Направление: `x` или `y` |
| `l1`, `l2` | Ширина захвата, м |
| `U1`, `U2` | Рабочая скорость, м/с |
| `hx1`, `hx2` | Длина машин, м |
| `hy1`, `hy2` | Ширина машин, м |
| `coord1_x`, `coord1_y` | Старт первой машины, м |
| `coord2_x`, `coord2_y` | Старт второй машины, м |
| `orient1`, `orient2` | Ориентация, градусы |

Необязательные столбцы:

| Столбец | Значение по умолчанию |
| --- | --- |
| `field_x`, `field_y` | `240`, `120` м рабочей части |
| `turn_zone_width` | `10` м с каждого конца, сверх рабочей части |
| `allowed_gap_percent` | `0%` |
| `Vtravel1`, `Vtravel2` | `U × 1.25` |
| `Vturn1`, `Vturn2` | `U × 0.75` |
| `R1`, `R2` | `max(2.5, hx / 2, hy / 2)` |

## 13. Выходные показатели

| Показатель | Содержание |
| --- | --- |
| `T_strat*` | Время завершения стратегии |
| `T1_strat*`, `T2_strat*` | Время каждой машины |
| `work_strat*` | Суммарный рабочий путь |
| `deadhead_strat*` | Суммарный порожний путь |
| `overlap_strat*` | Площадь повторного покрытия |
| `uncovered_strat*` | Площадь пропусков |
| `coverage_strat*` | Процент покрытия |
| `axis_strat*` | Выбранное направление |
| `turns_strat*` | Суммарное число разворотов |
| `delay_strat*` | Выбранная задержка запуска |
| `status_strat*` | Допустимость или причина отклонения |
| `Winner` | Лучшая стратегия |
| `Winner_time` | Её итоговое время |

`strat1` соответствует делению пополам, `strat2` — полосам, `strat3` —
делению по производительности.

## 14. Явные допущения

- Поле прямоугольное, внутренних препятствий нет.
- Разворотные зоны заранее убраны.
- Скорость каждого режима постоянна.
- Ускорение, торможение и буксование не моделируются.
- Машина представлена защитной окружностью.
- Движение задним ходом отсутствует.
- После последнего прохода машина въезжает в разворотную зону и останавливается
  в ближайшей безопасной точке, не доезжая без необходимости до внешнего края.
- Возвращение в отдельную базовую точку не реализовано.
- Максимальная задержка старта — 180 секунд.

## 15. Граница проекта

Итоговый комплект включает приложение, генератор, расчётное ядро, обязательные
сценарии А–Г, маршруты, сравнение алгоритмов и автоматические программные тесты.
Разработка физического робота, протокола телеметрии, оборудования и натурных
испытаний сознательно не выполняется.
