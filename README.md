# Prime

Prime — настольный планировщик совместной уборки прямоугольного поля двумя
автономными машинами. Программа строит маршруты, сравнивает способы распределения
рабочих проходов, проверяет покрытие и возможные столкновения, при необходимости
добавляет задержку запуска и выбирает лучший допустимый план.

Проект включает графическое приложение, независимое расчётное ядро, генератор
тестовых XLSX-таблиц, подготовленные примеры расчётов и готовую сборку для Windows.

## Возможности

- расчёт одного сценария через графическую форму;
- пакетная обработка XLSX с произвольным количеством сценариев;
- сравнение трёх стратегий организации работы:
  - деление поля пополам;
  - чередование рабочих полос;
  - деление пропорционально производительности машин;
- подбор направления проходов вдоль X или Y в пакетном режиме;
- учёт ширины захвата, скоростей, габаритов, радиуса поворота и стартового
  положения каждой машины;
- построение переездов, рабочих проходов и разворотов;
- проверка пропусков, перекрытия, допустимости разворотных зон и столкновений;
- устранение конфликтов задержкой запуска одной из машин;
- визуализация выбранного маршрута;
- экспорт результатов, маршрутов и схемы в XLSX и PNG.

## Быстрый запуск

### Готовая Windows-сборка

Python и установка зависимостей не требуются:

```powershell
.\dist\Prime.exe
```

### Запуск из исходного кода

Проект настроен на Python 3.14.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python main.py
```

Основные зависимости: PyQt6, pandas и openpyxl.

### Пересборка Windows-приложения

После установки зависимостей готовый однофайловый EXE можно пересобрать через
PyInstaller:

```powershell
python -m PyInstaller `
  --noconfirm `
  --clean `
  --onefile `
  --windowed `
  --name Prime `
  --distpath dist `
  main.py
```

Результат будет сохранён как `dist\Prime.exe`.

## Работа с приложением

### Частный расчёт

На вкладке «Рассчитать частный случай» задаются:

- размеры поля, направление проходов и ширина разворотной зоны;
- допустимый процент пропусков;
- режим завершения маршрута;
- характеристики, координаты и ориентация двух машин.

Приложение сравнивает три стратегии, показывает их показатели и рисует лучший
маршрут. Выбранное в форме направление применяется ко всем стратегиям. Для
сравнения X и Y нужно выполнить два расчёта.

Результат можно сохранить как:

- XLSX-отчёт с исходной конфигурацией, итоговыми показателями и маршрутами обеих
  машин;
- PNG-схему выбранного плана.

### Пакетный расчёт

На вкладке «Загрузить таблицу»:

1. Выберите входной файл `.xlsx`.
2. При необходимости измените путь результата.
3. Нажмите «Запустить расчёт».

В интерфейсе отображаются первые 100 строк, но обрабатывается вся таблица.
Для каждой стратегии пакетный режим проверяет оба направления проходов и
сохраняет лучший вариант. В результирующий XLSX входят исходные данные и новые
расчётные столбцы.

Готовые примеры находятся в каталоге [`computations`](computations):

- `required_scenarios.xlsx` и `required_scenarios_result.xlsx`;
- `synthetic_scenarios.xlsx` и `synthetic_scenarios_result.xlsx`.

## Формат входного XLSX

Каждая строка описывает отдельный сценарий. Все размеры задаются в метрах,
скорости — в м/с, ориентация — в градусах.

### Обязательные столбцы

| Столбец | Описание |
| --- | --- |
| `s` | Исходное направление проходов: `x` или `y` |
| `l1`, `l2` | Ширина захвата машин |
| `U1`, `U2` | Рабочая скорость |
| `hx1`, `hx2` | Длина машин |
| `hy1`, `hy2` | Ширина машин |
| `coord1_x`, `coord1_y` | Стартовые координаты первой машины |
| `coord2_x`, `coord2_y` | Стартовые координаты второй машины |
| `orient1`, `orient2` | Начальная ориентация машин |

### Необязательные столбцы

| Столбец | Значение по умолчанию | Описание |
| --- | ---: | --- |
| `scenario_id` | Номер строки | Идентификатор сценария |
| `field_x` | `240` | Размер поля вдоль X |
| `field_y` | `120` | Размер поля вдоль Y |
| `turn_zone_width` | `10` | Ширина разворотной зоны с каждого конца прохода |
| `allowed_gap_percent` | `0` | Допустимая доля необработанной площади, % |
| `return_to_start` | `false` | Возвращать ли машины к стартовым точкам |
| `Vtravel1`, `Vtravel2` | `U × 1.25` | Скорость порожнего переезда |
| `Vturn1`, `Vturn2` | `U × 0.75` | Скорость разворота |
| `R1`, `R2` | `max(2.5, hx / 2, hy / 2)` | Минимальный радиус поворота |

Для `return_to_start=true` стартовая точка машины должна находиться на границе
поля. Логические значения можно задавать как `true/false`, `yes/no`, `да/нет`
или `1/0`.

## Результаты расчёта

Для каждой стратегии используются суффиксы:

- `strat1` — деление пополам;
- `strat2` — чередование полос;
- `strat3` — деление по производительности.

Основные выходные столбцы:

| Столбец | Описание |
| --- | --- |
| `axis_strat*` | Выбранное направление проходов |
| `T_strat*` | Время завершения последней машины |
| `T1_strat*`, `T2_strat*` | Время первой и второй машины |
| `work_strat*` | Суммарный рабочий путь |
| `deadhead_strat*` | Суммарный порожний путь |
| `overlap_strat*` | Площадь повторного покрытия |
| `uncovered_strat*` | Необработанная площадь |
| `coverage_strat*` | Процент покрытия |
| `turns_strat*` | Общее количество разворотов |
| `delay_strat*` | Назначенная задержка запуска |
| `status_strat*` | Допустимость плана или причина отклонения |
| `Winner` | Лучшая стратегия |
| `Winner_axis` | Направление лучшего плана |
| `Winner_time` | Итоговое время лучшего плана |

XLSX-отчёт частного расчёта содержит листы `configuration`, `results`,
`route_machine_1` и `route_machine_2`.

## Генерация сценариев

`generate.py` создаёт две воспроизводимые входные таблицы:

- матрицу из 162 сочетаний характеристик машин и направлений;
- компактный набор контрольных сценариев.

Запуск с именами файлов по умолчанию:

```powershell
python generate.py
```

Выбор путей вручную:

```powershell
python generate.py `
  --output scenarios.xlsx `
  --required-output required_scenarios.xlsx
```

Генератор формирует только входные данные. Для получения статистики созданный
XLSX нужно обработать в приложении.

## Как работает планировщик

1. Формирует геометрию рабочей области с учётом разворотных зон.
2. Распределяет проходы между машинами по трём стратегиям.
3. Перебирает порядок проходов и сторону входа для каждой машины.
4. Строит рабочие участки, переезды и дуги разворотов.
5. Отклоняет варианты с недопустимыми пропусками или недостаточной шириной
   разворотной зоны.
6. Проверяет совместное движение машин во времени с учётом их габаритов.
7. При конфликте перебирает задержки запуска от 0 до 180 секунд с шагом 5 секунд.
8. Выбирает допустимый план с минимальным временем завершения пары. При близком
   времени сравниваются порожний путь, затем площадь перекрытия.

## Структура проекта

```text
.
├── main.py                         # GUI, XLSX-ввод/вывод и отчёты
├── planner.py                      # расчётное ядро и проверка маршрутов
├── generate.py                     # генератор входных сценариев
├── requirements.txt                # зависимости Python
├── pyrightconfig.json              # настройки статического анализа
├── computations/                   # примеры входных данных и результатов
├── dist/Prime.exe                  # готовая Windows-сборка
├── APP_DOCUMENTATION.md            # описание приложения и модели
├── GENERATOR_DOCUMENTATION.md      # описание генератора
├── TASK1_EXPLANATORY_NOTE.md       # пояснительная записка по расчётной части
├── TASK2_ALGORITHM_COMPARISON.md   # сравнение стратегий
└── TASK2_CONFLICT_AND_FAILURE_TEST_PROTOCOL.md
                                      # проверки конфликтов и отказов
```

Расчётное ядро не зависит от PyQt6: модели `Machine`, `FieldGeometry`, `Route` и
`Plan`, построение траекторий и выбор стратегии находятся в `planner.py`.
`main.py` отвечает за пользовательский интерфейс, проверку табличных данных,
фоновые вычисления и экспорт.

## Допущения и ограничения

- поле прямоугольное и не содержит внутренних препятствий;
- разворотные зоны считаются заранее освобождёнными;
- скорости на каждом типе участка постоянны;
- ускорение, торможение, буксование и движение задним ходом не моделируются;
- габарит машины при проверке столкновений заменяется защитной окружностью;
- безопасность оценивается по рассчитанным маршрутам, а не по телеметрии реальных
  машин;
- задержка старта ограничена 180 секундами;
- приложение является цифровым планировщиком и не управляет физической техникой.
