# Протокол проверок конфликтов и отказов

## Система планирования совместной уборки двумя автономными машинами

Кейс: «Разработка системы планирования автоматизированной уборки (АТ10-3)»  
Олимпиада: «Иннагрика 2026»  
Дата проверки: 18 ноября 2026 года  
Версия протокола: 1.0

---

## 1. Цель проверки

Цель проверки — подтвердить, что планировщик:

- обнаруживает опасное сближение двух машин с учётом времени движения;
- не считает конфликтом пересечение одной точки в разные моменты времени;
- при возможности устраняет конфликт задержкой запуска одной из машин;
- отклоняет маршрут, если безопасную задержку подобрать невозможно;
- не допускает выполнение геометрически невозможного маршрута;
- отклоняет исходные данные, по которым нельзя выполнить корректный расчёт;
- выдаёт понятную причину отказа.

Отдельно в протокол включены проверки отказов связи, локализации и локального
контроллера. Эти проверки должны выполняться на интеграционном стенде с
контроллерами машин. Текущий программный макет моделирует планирование маршрутов,
но не содержит канал связи с физической техникой.

## 2. Проверяемые компоненты

| Компонент | Назначение |
| --- | --- |
| `planner.py` | Построение маршрутов, расчёт защитных радиусов, проверка конфликтов и подбор задержек |
| `main.py` | Проверка входных данных, обработка сценариев и формирование результатов |
| `computations/synthetic_scenarios.xlsx` | Набор из 162 сочетаний характеристик машин |
| `computations/synthetic_scenarios_result.xlsx` | Результаты пакетной проверки 162 сценариев |

Проверка выполнена в Windows с использованием Python 3.14.3, pandas 3.1.1 и
openpyxl 3.1.5.

## 3. Правила определения конфликта

Каждая машина представляется защитной окружностью. Её радиус охватывает корпус,
жатку и дополнительный запас безопасности 0,25 м.

Конфликт фиксируется, если в один и тот же момент расстояние между центрами
машин становится меньше или равно сумме их защитных радиусов. Простое
пересечение линий маршрутов без совпадения по времени конфликтом не считается.

Для устранения конфликта планировщик проверяет задержку запуска одной из машин:

- минимальная задержка — 0 секунд;
- максимальная задержка — 180 секунд;
- шаг перебора — 5 секунд;
- выбирается безопасный вариант с наименьшим временем завершения пары.

Если ни один вариант задержки не обеспечивает безопасное движение, кандидат
получает статус `столкновение не устраняется задержкой` и исключается из выбора.

После завершения маршрута машина считается находящейся в конечной точке до
завершения работы второй машины. Это исключает выбор плана, при котором вторая
машина позднее проезжает через место парковки первой.

## 4. Критерии успешности

Проверка считается пройденной, если:

1. Одновременное опасное сближение всегда обнаруживается.
2. Пересечение траекторий в разные моменты не создаёт ложного конфликта.
3. Найденная задержка действительно устраняет конфликт.
4. Задержка не превышает 180 секунд.
5. Неустранимый конфликт приводит к отклонению маршрута.
6. Недопустимый маршрут не участвует в выборе лучшего плана.
7. Ошибочные данные не приводят к продолжению расчёта с неверными значениями.
8. Пользователь получает конкретное сообщение о причине отказа.

## 5. Проверки конфликтов

Для точечных проверок использованы искусственно заданные сегменты маршрутов.
Это позволяет заранее знать, в какой точке и в какой момент должно произойти
сближение.

| Код | Проверяемая ситуация | Ожидаемый результат | Фактический результат | Итог |
| --- | --- | --- | --- | --- |
| `C-01` | Две машины пересекают одну точку в один момент | Конфликт обнаружен | Одновременное пересечение обнаружено | Пройдено |
| `C-02` | Траектории пересекаются, но временные интервалы движения не совпадают | Конфликта нет | Пересечение в разные моменты не признано столкновением | Пройдено |
| `C-03` | Проверяются два полных маршрута с одновременным пересечением | Маршруты признаны конфликтующими | Конфликт полного маршрута обнаружен | Пройдено |
| `C-04` | Одновременный запуск создаёт конфликт, но машины можно развести по времени | Назначена минимальная безопасная задержка | Второй машине назначена задержка 5 секунд | Пройдено |
| `C-05` | Обе машины начинают движение из одной точки | План отклонён независимо от задержки | Безопасная задержка в диапазоне 0–180 секунд не найдена | Пройдено |
| `C-06` | Первая машина завершила маршрут и стоит в точке, через которую позднее проходит вторая | Конфликт с припаркованной машиной обнаружен | Конечная стоянка учтена при проверке | Пройдено |

### Результат раздела

Пройдено 6 из 6 проверок. Ошибок обнаружения временных конфликтов не выявлено.

## 8. Проверки отказов исполнительного уровня

Следующие проверки относятся к взаимодействию центрального планировщика с
локальными контроллерами машин. Они оформлены как обязательная программа
интеграционных испытаний. Для их выполнения необходим стенд, передающий
телеметрию и принимающий команды движения.

| Код | Имитируемый отказ | Способ проверки | Требуемая реакция системы | Текущий статус |
| --- | --- | --- | --- | --- |
| `R-01` | Потеря связи с машиной | Прекратить поступление телеметрии во время движения | Завершить только разрешённый безопасный манёвр либо перейти в `SAFE_STOP`; неподтверждённый участок не считать обработанным | Ожидает стенда |
| `R-02` | Устаревшая телеметрия второй машины | Передавать сообщения с временной меткой старше допустимого порога | Запретить вход в общую опасную зону и остановить движение в безопасной точке | Ожидает стенда |
| `R-03` | Недостоверная локализация | Передать признак потери координат или недопустимо низкого качества позиционирования | Запретить переход к `WORK`, `TRAVEL` и `TURN`; выполнить безопасную остановку | Ожидает стенда |
| `R-04` | Аварийный сигнал локального контроллера | Подать аварийный флаг во время выполнения сегмента | Немедленно прекратить выполнение задания; локальная остановка имеет приоритет над командами планировщика | Ожидает стенда |
| `R-05` | Получена устаревшая версия маршрута | Повторно отправить старое задание после перестроения маршрута | Отклонить устаревшую команду; не запускать уже выполненный сегмент повторно | Ожидает стенда |
| `R-06` | Машина отклонилась от запланированной траектории | Передать координату за допустимым коридором маршрута | Повторно проверить прогноз; при необходимости ограничить скорость, остановить машину или перестроить остаток маршрута | Ожидает стенда |
| `R-07` | Связь восстановлена после остановки | Возобновить передачу телеметрии после `SAFE_STOP` | Проверить координаты обеих машин, сформировать новую версию общего плана и только затем разрешить продолжение | Ожидает стенда |

Статус «Ожидает стенда» не означает ошибку расчётного ядра. Эти функции
относятся к исполнительному уровню, которого нет в текущей версии цифрового
планировщика.

## 10. Ограничения проведённой проверки

- поле считается прямоугольным и не содержит внутренних препятствий;
- скорости на сегментах постоянны, разгон и торможение отдельно не моделируются;
- машина представлена защитной окружностью;
- задержка запуска перебирается с шагом 5 секунд;
- динамические отказы связи и датчиков описаны, но без аппаратного стенда не
  воспроизводились;
- результат подтверждает корректность программной модели, но не заменяет
  натурные испытания системы аварийной остановки.
